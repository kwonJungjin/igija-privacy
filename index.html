이기자 개인정보처리방침

시행일: 2026년 9월 25일 · 앱: 이기자 · 운영 주체: 이기자 · 문의: weneedsomeigija@outlook.com

이기자는 사용자가 정한 앱·웹사이트 사용 계약과 시간 제한을 기기에서 집행하는 Android 앱이다. 계정 없이도 로컬 차단·과업·장부를 사용할 수 있다. 앱에서 제공하는 계정 연결, 사진 비교, 선생, 대화형 리캡, 스쿼드는 각각 별도 선택과 동의를 거친다. 가입하거나 이 방침을 확인했다는 이유만으로 사진을 보내거나 AI 대화·기억 저장·스쿼드 공유를 시작하지 않는다. 이전 익명 선생 자료는 새 계정으로 자동 합치지 않는다. 광고·분석 SDK는 사용하지 않는다.

1. 처리하는 정보

앱 사용정보

사용정보 접근을 허용하면 이기자 감시 서비스가 시작된 뒤 첫 성공한 Android 사용정보(UsageStats) 조회에서 기기가 부팅된 뒤의 범위 중 최대 24시간에 해당하는 앱 전환 기록을 한 번 확인한다. 이 첫 조회는 직전 화면 앱을 놓치지 않고 감시의 최초 상태를 정하기 위한 초기 seed이며, 조회 결과 전체를 보존하지 않고 그 범위에서 가장 최근에 포그라운드로 전환한 1건만 서비스의 초기 목격으로 보존한다. 그 뒤 감시 서비스의 일반 조회와 대시보드 조회는 최근 10분의 앱 전환 기록을 확인한다. 두 조회 범위에는 계약 대상이 아닌 다른 앱의 패키지명과 전환 시각도 포함될 수 있다. 감시 중에는 조회한 원기록 전체가 아니라 앱 전환 또는 차단 상태가 바뀐 시점의 패키지명, 시각, 차단 상태만 기기 안의 장부에 저장한다.

설치 앱 정보

사용자가 '앱 목록 불러오기'를 누르면 런처에서 실행할 수 있는 설치 앱의 이름, 패키지명, 아이콘을 읽는다. 전체 목록과 아이콘은 선택 화면에만 사용하고 목록 자체를 저장하지 않는다. 사용자가 선택한 앱의 패키지명은 계약과 규칙 이력에 저장한다. 저장한 규칙의 대상 앱 이름과 아이콘은 규칙 목록을 표시할 때마다 그 패키지만 Android에서 다시 읽어 보여 주며 저장하지 않는다.

독립 앱 정책

독립 앱 정책은 Android 사용정보(UsageStats)에서 현재 화면 앱의 패키지명을 읽어 저장된 규칙과 비교한다. 사용자가 직접 만든 규칙의 ID·이름·저장 순서·ON/OFF, 선택한 앱 패키지명과 정규화 도메인, 항상 차단·요일별 시간창 또는 오전 6시 기준 공유 일일 사용 한도는 앱 정책용 로컬 SharedPreferences에 저장한다. 일일 한도 사용량은 규칙 ID·오전 6시 기준 period·확실히 관찰한 누적 밀리초로 저장한다. 설치 앱 전체 목록과 아이콘은 저장하지 않는다. 사용자가 규칙 하나를 잠그거나 전체 잠금(Strict 모드)을 시작하면, 앱이 이 설치에서 처음 잠글 때 생성한 임의 잠금 식별자와 전체 잠금 상태(세대 ID·시작·해제 시각)는 백업 제외 igija_app_rule_strict_v14 SharedPreferences에 저장하고, 개별 잠금의 해제 시각과 그 식별자 사본은 해당 규칙과 함께 일반 규칙 저장소 igija_app_rules에 저장한다. 이 식별자는 기기 하드웨어나 계정 식별자가 아니며 개발자 서버로 전송하지 않는다. 다만 규칙에 포함된 사본은 Android 백업·기기 이전에 포함될 수 있다. 잠금이 유효한 동안 앱 안에서는 그 규칙의 완화·OFF·삭제와 감시 OFF를 제공하지 않으며, 더 세게 바꾸거나 기간을 늘리는 것만 저장한다. 이전 버전에서 별도로 등록한 웹사이트 차단 목록은 업데이트 뒤 차단 탭을 처음 열 때 같은 도메인의 항시 차단 규칙으로 옮겨 igija_app_rules에 두고, 옮기지 못한 항목은 옮길 때까지 별도 목록으로 남아 계속 차단되며 사용자가 지울 수 있다.

Strict 고정기간 계약

사용자가 별도 계약 화면에서 명시 확인한 경우에만 Strict 대상 앱 패키지명·정규화 도메인, 계약 시간대, 최초 고정기간, 1~7일 자동연장 기간, 출소 뒤 완충 기간과 하루 허용량을 backup 제외 SharedPreferences에 저장한다. 현재 회차·만기 06:00·회차당 한 번의 출소심사 token·출소 예약 또는 유지·시간 증거 동결·D-2/D-1 알림 게시·완충 일차와 사용량·일반 규칙 handoff 상태도 함께 저장한다. Strict 영수증은 contract/cycle/rule ID, 닫힌 상태·시각·bounded count만 Room 장부에 기록하며 방문 URL·자유서술 이유·선생 대화를 복사하지 않는다.

브라우저 웹주소

사용자가 등록한 도메인을 별도로 항상 차단하거나 몸값 경제의 공동 담보, 공유 일일 시간 제한 또는 Strict 표적으로 집행하기 위해 다음 정보를 처리한다. Android 13 이상에서 사용자가 별도 접근성 고지에 동의하고 Android 접근성 설정에서 '이기자 웹주소 차단'을 직접 켠 뒤, 사용정보 접근이 허용되고 이기자 감시가 실행 중이며 별도 차단 목록·담보·공유 일일 한도·Strict의 등록 도메인이 있을 때만 접근성 서비스가 Chrome·삼성 인터넷·Brave·Opera 정식판의 창 변경·창 내용 변경·입력 포커스 이벤트를 받도록 설정한다. Android가 전달하는 접근성 이벤트에는 화면 메타데이터가 포함될 수 있다. 이기자는 접근성 cache와 하위 항목 선반입을 끄고, 작동 중에만 Android가 제공하는 상호작용 가능한 창 목록에서 기본 화면의 입력 포커스를 가진 창이 정확히 하나인지 확인한다. 그 창의 앱 식별자가 같은 검사 대상 브라우저일 때만 그 창의 미리 정한 주소창 항목을 찾는다. 다른 창의 하위 항목은 찾지 않는다. 주소 입력칸이 선택된 동안에는 반환 노드의 문자열을 차단이나 시간 계산에 사용하지 않는다. 선택이 풀리면 주소창 항목의 화면 글자와 접근성 설명 중 웹주소로 해석되는 도메인을 등록한 목록과 기기 안에서 비교한다. 검색어처럼 웹주소로 해석되지 않는 문자열도 주소창 노드에 포함돼 전달될 수 있다. 차단 화면이 보이거나 허용 중인 담보·공유 일일 한도·Strict 도메인의 체류시간을 계산하는 동안에도 차단 화면 자체가 아니라 입력 포커스를 유지한 같은 브라우저 창 하나만 골라 주소창 항목을 짧은 간격으로 재검사한다. 다른 앱이거나 입력 포커스 창이 없거나 둘 이상이거나 주소 판독이 불확실하면 하위 항목을 찾지 않고 차단 화면과 시간 계산을 중단한다. 페이지 본문이나 일반 입력칸을 따로 찾거나 그 문자열을 판정에 사용하지 않지만, Android가 이벤트·창 목록·반환 노드에 포함해 전달한 메타데이터 자체의 수신까지 막는다고 약속할 수는 없다. 사용자가 등록한 정규화 도메인은 해당 로컬 규칙이나 계약에 저장하고, 확실한 체류 구간만 몸값 그룹 또는 해당 일일 한도에 합산한다. 검사한 주소창 문자열과 방문한 전체 URL은 저장하지 않고 개발자에게 전송하지 않는다.

계약과 사용 상태

담보 그룹의 이름과 내부 ID, 선택한 앱의 패키지명, 사용자가 담보로 등록한 정규화 도메인, 별도로 등록한 차단 도메인, 하루 예산, 굿나잇 시간, 앱·담보 웹사이트의 그룹 합산 사용 시간, 과업으로 받은 시간, 멀티플 단계와 날짜 상태를 저장한다.

과업 실행 자료와 시작 사진

사용자가 과업 실행마다 입력한 행동 문장, 선택한 제목, 수행 시간, 시작 사진, 적용된 유한 증거 프로필과 증언 표지, 시작·완료·포기·세션 유실 시각, 지급 시간과 사용자가 직접 저장한 자주 쓰는 과업을 저장한다. 행동 문장·선택 제목·시작 사진·증언 표지는 시간·지급 장부와 분리된 삭제 가능 실행 자료다. 새 형식의 장부 사건은 이 자료 대신 taskRunId와 집행·경제 값만 기록한다. 사용자가 과업 선언 화면에서 '시작 사진 찍기'를 누르고 CAMERA 권한을 허용하면 CameraX가 카메라 프레임을 이기자 안의 프리뷰에 전달하고, 사용자가 촬영한 한 장을 이기자가 내부 앱 전용 JPEG로 쓴다. 촬영본은 세션을 시작하기 전에 방향을 화소에 반영한 새 JPEG로 다시 써서 원본의 EXIF·GPS·내장 썸네일을 보존하지 않는다. 현재 제공하는 기본 프로필은 사진 내용이나 과업 완료 여부를 판독하지 않는다. 이 기본 프로필에서는 제목과 행동 문장을 사진 판독 입력으로 쓰지 않고, 저장된 행동 문장은 이기자 선생에게 자동 전송하지 않는다. 카메라 취소·명시 포기·세션 생성 실패 때 새 내부 사진을 정리한다. 촬영·자료 생성 중 앱 프로세스가 예기치 않게 끝나 남은 미완료 임시 사진과 경제 흔적 없는 준비 자료는 다음 실행에서 제한된 수만 정리한다.

앱 운영 장부

감시 ON·OFF와 복구 결과, 사용정보 접근의 해제·복구, 차단 표시·해제 시각, 규칙 변경, 재부팅 횟수, 시계 변경 감지, 일별 판정과 스트릭을 저장한다. 독립 앱 정책의 규칙변경과 그 시점의 전체 규칙 사본, 앱 전환·차단 상태가 바뀐 시점의 패키지명·시각·규칙 ID·차단 사유는 같은 Room 데이터베이스에 scope=app_policy로 분리해 저장한다. Strict 계약·회차·출소·자동연장·완충·handoff·시간 동결 영수증은 scope=strict_v1로 분리한다. 이 범위의 사건은 몸값 경제의 일별 판정·스트릭·계보·리캡 입력에서 제외한다. 이 정보는 계약과 앱 정책 집행, 상태 복원, 장부와 리캡 표시에 사용한다.

선제적 차단과 구조화 심문 기록

사용자가 선제적 차단 설정에서 별도로 `취소 뒤 구조화 심문 기록 사용`을 켠 경우에만, 선택한 앱·닫힌 발동 조건·발동 상한·cooldown·일회성 lease를 기기에 저장한다. 조치를 취소한 뒤에는 사용자 문장에 1~360 범위의 숫자+`분`이 정확히 하나 있을 때 그 첫 숫자 주장, 첫 취소·재잠금·최종 취소 시각, 재잠금까지 걸린 시간, 취소 뒤 선택 앱의 foreground 체류시간을 연속 단조시계 관측이 확실한 경우에만 구조화해 저장한다. 5초를 넘는 관측 공백, 재부팅, process death, 화면 OFF·잠금, 사용정보 접근 실패가 있으면 실제 체류시간은 추정하지 않고 unavailable로 둔다. 사용자가 채팅에 쓴 자유서술 이유, 세부 사용 timeline, 다른 앱 목록, 방문 URL은 이 구조화 기록에 복사하지 않는다. 별도 AI 전송 고지까지 동의한 사용자가 채팅을 보낼 때에는 선택 앱의 표시 이름, 현재 조치 상태·종류·닫힌 발동 조건·기준 횟수와 같은 활성 계약·같은 앱의 최근 완료 구조화 기록 최대 3건에서 첫 숫자 주장·확실히 관측한 실제 사용 분·취소 또는 재잠금 결과만 개발자 서버를 거쳐 OpenAI로 보낼 수 있다. 앱 package, 계약·사건 ID, 자유서술 이유, 세부 timeline, 정확한 취소 시각은 이 AI 문맥에 넣지 않는다.

온보딩 진행 상태

첫 계약을 마치기 전에는 현재 단계와 편집 중인 그룹 이름, 예산, 선택 앱과 담보 도메인을 저장해 앱을 다시 열었을 때 이어서 진행한다. 민감정보 공개문과 웹주소 접근성 별도 고지의 확인 버전도 기기에 저장한다.

공통 계정과 기능별 동의

사용자가 가입·로그인 화면에서 선택한 로그인 서비스로 진행하면, 그 서비스가 제공하는 계정 식별 정보와 동의한 프로필·이메일을 Supabase Auth에서 처리해 이기자 계정에 연결한다. 카카오 로그인은 카카오의 인증·동의 화면을 거친다. 이메일 로그인이 제공되는 경우에는 이메일 인증과 발송업체 처리를 해당 화면에서 따로 안내한다. 이기자 서버에는 계정·기기 연결 식별자와 상태, 기능별 동의와 철회 이력, 요청 중복 방지·처리 상태가 저장된다. 기능별로 다른 내부 식별자와 짧은 수명의 자격을 사용하며, 로그인 인증값을 AI 공급자나 다른 사용자에게 보내지 않는다. 앱의 로그인 정보는 Android Keystore로 암호화해 백업 제외 영역에 보관한다. 기존 익명 선생의 계정·대화·기억을 새 계정에 자동 이전하지 않는다.

선택한 시작 사진의 비교

사용자가 별도 사진 기능에 동의하고 새 촬영본을 확인한 뒤 전송을 선택할 때만, 정규화한 JPEG 한 장과 해당 과업의 행동 문장을 개발자 Supabase 서버를 거쳐 OpenAI에 보낸다. 기본 사진 기록은 이 전송을 요구하지 않는다. 갤러리 전체나 다른 과업의 사진을 자동 수집하지 않는다. 비교 결과는 사진과 행동 문장의 관계에 대한 제한된 판단이며, 과업 완료·보상·차단 변경을 결정하지 않는다. 앱은 사용자가 결과를 본 뒤 과업 시작 여부를 직접 선택하게 한다. 개발자 서버는 이 비교용 사진과 행동 문장 원문을 데이터베이스나 객체 저장소에 보관하지 않고 요청 처리 동안만 사용한다. 중복 요청 방지용 식별자·내용을 직접 담지 않은 지문·처리 상태·제한된 판정·호출량은 별도로 저장한다. 기기의 촬영본과 실행 자료는 앞서 설명한 로컬 과업 자료 삭제 규칙을 따른다. 비교 작업 기록은 생성 후 최대 24시간이 지나면 만료되고, 물리 삭제는 정리 작업이 성공한 때 이뤄진다. 명시 삭제 뒤에도 원래 만료 시각까지 중복 처리를 막는 표지가 유효하며, 만료된 표지는 정리 작업이 성공할 때 회수한다.

공통 계정으로 사용하는 선생

사용자가 선생 동의 뒤 직접 보낸 현재 문장, 제한된 최근 대화와 앱 상태 요약을 개발자 서버와 OpenAI에 보내 답변·기억 후보·행동 초안을 받는다. 계정 대화는 현재 화면의 메모리에만 두며 화면 이탈·취소·계정 변경 때 비운다. 이전 익명 대화 저장소를 읽어 합치지 않는다. 로컬 위기 분류에 해당하는 입력은 고정된 기기 응답으로 처리하고 서버에 보내지 않는다. 사진 원본·방문 URL·설치 앱 전체 목록·경제 장부 원문은 선생의 대화 문맥으로 보내지 않는다. 서버는 요청 식별자·지문·처리 상태·호출량을 보관하고 응답 유실 대응용 구조화 답변을 24시간 동안 유효하게 둔다. 이 답변에는 모델이 제안한 문장이나 사용자가 한 말의 인용이 포함될 수 있다. 대화 입력 전체를 대화 이력 표로 축적하지 않지만, 서버에 사용자 발언의 일부가 전혀 남지 않는다고 약속하지 않는다. 만료된 응답은 보존 정리 작업이 성공할 때 물리적으로 회수한다.

확인한 기억과 독립 키 보관

이 버전에서는 기억 끄기와 확인 후 저장을 선택할 수 있다. 자동 반영 후 알림은 새로 선택할 수 없으며, 새 기억을 자동으로 저장하지 않는다. 이전에 저장된 자동 반영 설정이나 기억 자료를 앱이 임의로 바꾸거나 삭제하지 않는다. 사용자는 기존 설정을 확인하고 기억 끄기 또는 확인 후 저장으로 직접 변경할 수 있으며, 조회·철회·삭제 권리는 유지된다. 기억 끄기는 새 기억 저장과 기존 기억의 대화 재사용을 중단하는 설정이며 이미 저장한 기억의 삭제는 아니다. 확인 후 저장에서는 사용자가 후보 문장과 인용한 발언을 보고 저장을 선택하기 전까지 영구 기억으로 쓰지 않는다. 기억하지 않기를 선택하면 해당 후보를 폐기한다. 저장한 문장과 인용은 암호문으로 Supabase에 두고, 복호화 키와 내용 없는 폐기·복원 방지 장부는 Google Cloud Storage에 분리해 둔다. 서버는 사용자가 허용한 기억을 읽어 AI 답변 문맥으로 사용하며, 이때 필요한 평문이 서버 처리 메모리와 OpenAI 요청에 포함된다. 이는 서버가 내용을 볼 수 없는 종단간 암호화가 아니다. 저장 안내를 확인하기 전이나 동의·기억 사용 조건이 맞지 않으면 대화에 재사용하지 않는다. 사용자는 저장된 기억을 조회·수정·삭제할 수 있다. 기억을 끄거나 동의를 철회하는 것과 이미 저장한 기억을 삭제하는 것은 서로 다른 선택이다.

공통 계정의 대화형 리캡

선생 동의와 별도의 리캡 동의를 켰을 때 현재 대화의 사용자 발언에서 후보를 골라 확인 질문을 만든다. 질문·정정·애매한 답 확인에 필요한 원문 구절·직전 요약·현재 답을 Supabase 중계를 통해 OpenAI에 보낼 수 있다. 사용자가 명시적으로 긍정한 문장과 날짜만 기기의 리캡 장부에 저장한다. 거부·취소·확인 전 후보는 로컬 기록으로 저장하지 않는다. 서버의 리캡 작업 기록에는 원문 없는 요청 식별자·지문·상태·호출량을 두며, 리캡 질문·요약 원문을 재생용 응답으로 저장하지 않는다. 확인한 로컬 리캡은 자동 만료시키지 않으며 사용자가 조회·삭제할 수 있다. 리캡 동의 철회·로그아웃은 이미 저장한 로컬 리캡의 삭제가 아니다. 클라우드 동기화나 기존 익명 자료의 자동 병합은 하지 않는다.

초대 전용 스쿼드

스쿼드 기능이 제공되는 경우 별도 동의 뒤 초대·가입·목표 참여와 명시적인 수행 영수증 공유를 처리한다. 서버는 별명·모임·초대·회원과 역할, 목표·회차·참여 상태, 본인이 공유한 제한된 긍정 영수증과 집계 정보를 저장한다. 영수증에 사진·자유서술 대화·원문 과업 자료를 붙여 자동 공유하지 않는다. 공개 검색·공개 피드·순위·댓글·사진 공유·자동 과업 공유는 제공하지 않는다. 앱 안에서 특정 대상 신고와 개인 차단을 할 수 있다. 신고에는 대상 식별자·선택한 사유·처리 상태를 기록하며 신고 원문을 별도 복사하지 않는다. 신고·처리 기록은 신고 생성 뒤 90일 동안 보존 대상으로 관리하고, 이의 신청은 결정 뒤 168시간(7일) 이내 가능하다. 이의 신청으로 보존 기간을 연장하지 않으며, 만료 기록은 정리 작업이 성공할 때 물리적으로 회수한다. 스쿼드 자료 전체 삭제에서는 신고자·신고 대상과의 연결을 제거하지만 보존 기간 안의 신고·처리 기록 자체가 즉시 모두 없어지는 것은 아니다. 운영 대응 시간을 별도로 약속하지 않는다. 탈퇴·개인 차단·본인 영수증 삭제·스쿼드 자료 전체 삭제는 서로 다른 기능이며, 각 확인 화면에서 범위와 회차 표시 영향을 안내한다. 내보낸 파일은 사용자가 선택한 위치에 남으며 서버 기록 삭제·탈퇴와 함께 삭제되지 않는다.

이전 익명 선생 채팅과 익명 계정

사용자가 별도 AI 전송 고지에 동의하고 이기자 선생 화면에서 채팅을 보낸 때에만, 현재 채팅 원문과 서버로 보냈던 최근 USER·TEACHER 대화 중 최대 6개·총 2,400자, 앱이 미리 정한 유한한 축약 사실, 사용자가 직접 확인한 기억 명제를 처리한다. 축약 사실에는 활성 과업의 시작 사진 존재 여부와 오늘 지급 기록 존재 여부가 포함될 수 있고, 위 구조화 심문 기록을 별도로 켠 경우에는 선제 조치의 유한한 사실이 포함될 수 있다. 사진·지급 사실은 존재 여부만 나타내며 사진 내용이나 지급량을 나타내지 않는다. 다만 앱의 닫힌 로컬 규칙이 명시적인 자해·죽음·극단 위험 문구로 분류한 채팅과 폰 안의 로컬 명령·응답은 기기 안에서 끝내고 그 원문과 앱 문맥을 개발자 서버나 OpenAI로 보내지 않는다. 방문 URL 원문, 사진 원본·내용·경로·해시·판정 결과, 지급량, 설치 앱 전체 목록, Room 장부 payload는 선생 문맥으로 보내지 않는다. Supabase Auth가 임의 사용자 ID와 access·refresh token을 발급하며, 앱은 token을 Android Keystore의 AES-GCM key로 암호화해 백업 제외 SharedPreferences에 저장한다. 최근 USER·TEACHER 대화에는 폰 안에서 끝낸 위기 대화의 원문·고정 응답과 로컬 명령·응답도 포함하며, 같은 익명 사용자 ID에 결박하고 Android Keystore의 별도 AES-GCM key로 암호화해 최대 40개만 둔다. 이 로컬 전용 대화는 복원돼도 원격 최근 문맥에는 절대 넣지 않는다. 각 메시지 생성 뒤 24시간이 지나면 표시하거나 다음 AI 문맥에 쓰지 않고 다음 선생 진입·대화 저장·전송 또는 열린 화면의 60초 이내 주기 확인 때 암호문에서 제거하며, 새 메시지가 생겨도 오래된 메시지의 생성 시각과 만료 시각은 연장하지 않는다. 앱을 실행하지 않으면 암호화 바이트는 다음 선생 진입·대화 저장 또는 앱 데이터 삭제까지 남을 수 있다. Android 백업·기기 이전에서는 제외하고 사용자가 '새 대화'를 확인하면 vault 삭제 성공 뒤 현재 USER·TEACHER 대화를 즉시 지운다. 복원할 때에는 id·역할·텍스트·로컬 전용 여부·생성 시각만 되살리며 확인 전 기억 후보·행동 초안·답변 신고 버튼은 되살리지 않는다. 사용자가 아직 서버에 보존된 원격 AI 답변에서 '문제 있는 답변 신고'를 누르고 닫힌 사유 하나를 선택하면, 서버는 해당 익명 계정에 연결된 AI 답변 본문·응답 digest·선택한 사유·안전 모드·모델 및 prompt 버전·신고 시각을 검토용 신고 기록으로 보존한다. 사용자의 채팅 원문은 이 신고 기록에 복사하지 않으며 자유서술 신고문도 받지 않는다. 폰 안의 고정 위기 응답과 다른 사용자의 답변은 신고할 수 없다. 다만 응답 성립 여부를 확인하지 못한 요청 한 건은 중복 provider 비용을 막고 같은 ID·같은 익명 계정으로만 재확인하기 위해 client_turn_id, Supabase 익명 사용자 ID, 사용자 문장, 당시의 닫힌 축약 문맥, 생성 시각을 Android Keystore의 별도 AES-GCM key로 암호화해 기기에 보류한다. 재확인은 생성 뒤 최대 1시간만 허용한다. 성공하거나 사용자가 명시적으로 폐기·AI 연결 해제·계정 삭제·앱 데이터 삭제를 하면 지운다. 손상되거나 1시간이 지난 보류 요청은 다시 전송하지 않는다. 현재 익명 계정과 일치하지 않는 보류 요청도 다시 전송하지 않으며, 사용자가 폐기할 때까지 암호화 상태로 남아 새 평상 요청을 막는다. 선생이 만든 기억 후보와 행동 초안은 사용자 확인 전에는 앱 상태를 바꾸지 않는다.

이전 익명 선생의 대화형 리캡

사용자가 기존 AI 전송 동의와 별개인 대화형 리캡 동의를 직접 켠 경우에만, 선생은 현재 대화 화면·세션에서 사용자가 했다고 말한 일과 소감의 사용자 원문 구절을 골라 리캡에 남길지 물을 수 있다. 질문·정정·애매한 답 확인을 만들 때에는 같은 익명 계정으로 선택한 원문 구절, 직전 요약과 사용자의 현재 답 중 필요한 항목을 개발자 서버를 거쳐 같은 OpenAI provider에 추가 전송할 수 있다. 리캡용 provider 호출은 서버 UTC 날짜 기준 사용자당 하루 최대 5회다. 확인 전 후보·질문·요약은 Android retry vault나 Room에 저장하지 않고, 서버에는 원문 없는 operation ID·요청 digest·유한 상태·호출량만 둔다. operation terminal은 24시간 뒤 만료되고 다음 실제 retention sweep에서 물리 삭제될 때까지 남을 수 있다. 사용자가 명시적으로 맞다고 확인한 뒤에만 요약 문장·해당 로컬 날짜·출처 종류·안전 모드·확인 ID를 기기 Room의 리캡 전용 표에 저장한다. 확인 기록은 Android 백업이나 기기 이전에 포함될 수 있으며 앱 안에서 개별 또는 전체 삭제할 수 있다. 리캡 동의를 끄면 확인 전 후보·질문을 폐기하고 이미 확인한 기록은 자동 삭제하지 않는다.

2. 이용 목적

처리한 정보는 사용자가 정한 앱·웹사이트 사용 계약과 독립 앱 정책·공유 일일 시간 제한·Strict 고정기간 계약 집행, 대상 앱과 선택 웹사이트의 그룹 또는 규칙별 사용 시간 계산, 앱·시간창·웹주소 차단 화면 표시, 출소심사·자동연장·완충 상태 복원, 담보 앱·웹사이트 선택, 과업 수행과 시간 지급 기록, 과업 실행 자료·장부·오늘의 인증·리캡·스트릭 표시, 명시적으로 켠 감시의 정상 재부팅 뒤 복구, 권한·알림·저장 실패 상태 고지에 사용한다. 사용자가 별도로 켠 선제적 차단의 구조화 기록은 취소·재잠금 결과를 복원하고, 별도 AI 동의 뒤 사용자가 채팅에서 이유를 말할 때 확인 가능한 유한 숫자 사실을 선생 답변에 반영하는 데에만 사용한다. 이기자 선생 정보는 사용자의 채팅에 답하고, 확인 전 기억·행동 초안을 제안하고, 요청 중복·비용 상한·안전 분기를 적용하는 데에 사용한다. 별도 동의한 대화형 리캡 정보는 현재 대화에서 기록 후보를 묻고 사용자가 확인한 요약만 로컬 목격록으로 남기는 데 사용한다. 사용자가 직접 만든 문제 답변 신고는 해당 AI 답변을 확인하고 안전·품질 문제를 개선하는 데 사용한다.

3. 저장 위치와 외부 전송

계약·현재 상태·온보딩 상태, 담보로 등록한 도메인과 아직 규칙으로 옮기지 않은 별도 차단 도메인은 Android SharedPreferences에 저장한다. 독립 앱 정책과 공유 일일 시간 제한의 규칙·ON/OFF·선택한 앱·도메인·요일별 시간창·quota 및 규칙별 누적 사용량은 igija_app_rules와 igija_app_rule_runtime SharedPreferences에 저장한다. Strict 계약·회차·출소·완충·handoff 상태는 backup 제외 igija_strict_v1 SharedPreferences에 저장한다. 규칙 잠금·전체 잠금의 임의 식별자 원본과 전체 잠금 상태는 backup 제외 igija_app_rule_strict_v14 SharedPreferences에 저장한다. 선제적 차단 위임·lease는 backup 제외 SharedPreferences에, 구조화 심문 기록은 Android Keystore의 별도 non-exportable AES-GCM key로 암호화한 backup 제외 SharedPreferences에 저장한다. 이전 익명 선생의 최근 USER·TEACHER 대화는 익명 사용자 ID에 결박해 Android Keystore의 대화 전용 AES-GCM key로 암호화한 backup 제외 SharedPreferences에 저장한다. 선생 서버 삭제의 시도·미확인·서버 확인 뒤 로컬 정리 대기 상태는 원문이나 계정 ID 없이 별도 backup 제외 SharedPreferences에 저장한다. 사용자가 확인한 대화형 리캡은 요약 문장·로컬 날짜·출처·안전 모드·확인 ID를 Room의 리캡 전용 표에 저장한다. 선택 도메인 체류는 방문별 이력이 아니라 그룹 또는 규칙별 합산 사용시간과 사용자가 등록한 규칙 표적의 전이만 Room 장부와 SharedPreferences에 저장한다. 역사 장부와 일별 판정, scope=app_policy·scope=strict_v1 사건은 Room 데이터베이스에 저장한다. 새 실행의 행동 문장·선택 제목·시작 사진·증언 표지는 Android 자동 백업에서 항상 제외되는 내부 no-backup 저장소에 둔다. 사용자가 직접 저장한 자주 쓰는 과업의 제목·행동 문장·시간·프로필은 별도 SharedPreferences에 두되 backup XML에서 클라우드 백업과 기기 이전을 모두 제외한다. 새 과업 사진을 찍을 때는 외부 카메라 앱을 열지 않는다. CameraX가 카메라 프레임을 이기자 안의 프리뷰에 전달하고, 사용자가 촬영한 한 장을 이기자가 내부 앱 전용 JPEG로 쓴다. 이전 버전에서 촬영한 사진은 기존 외부 앱 전용 폴더에 남아 있을 수 있다. 이 사진은 표시 호환을 위해 읽지만 CameraX 전환 과정에서 자동 이관·삭제·재판독하지 않는다.

공통 계정 기능의 저장 위치와 외부 처리

계정 인증과 사진·선생·리캡·스쿼드 요청은 고정된 Supabase HTTPS 경로를 사용한다. 사진·선생·리캡의 AI 처리에 필요한 자료만 서버에서 OpenAI로 보내며, 스쿼드 자료를 이 AI 문맥에 자동 연결하지 않는다. 현재 운영 데이터베이스의 주 저장 리전은 Supabase의 AWS 서울이며, 기억의 독립 복호화 키·폐기 장부는 Google Cloud Storage의 서울 리전 버킷에 둔다. 기억 키 버킷은 공개하지 않고 객체 버전 관리·소프트 삭제·버킷 보관 정책을 사용하지 않는다. 이 두 저장소의 위치가 모든 외부 처리를 국내로 제한한다는 뜻은 아니다. OpenAI 프로젝트는 특정 지역에 한정하지 않는 Global 설정이며, 입력·출력의 학습용 공유는 꺼져 있고 Zero Data Retention은 적용하지 않는다. 앱에는 공개 프로젝트 키만 포함하고 OpenAI 키·Supabase 관리자 키·Google 서비스 계정 키·기억 복호화 키를 넣지 않는다. OpenAI 호출은 store=false로 전송하지만 이것이 모든 외부 보관을 없애는 것은 아니다. 기본 악용 방지 로그에는 입력·응답이 포함돼 최대 30일 남을 수 있고 법적 의무나 위해 방지 사유가 있으면 더 길어질 수 있다. 지원 모델의 캐시에는 암호화된 내부 표현이 최대 24시간 남을 수 있다. API 자료는 명시적으로 학습용 제공을 선택하지 않는 한 모델 학습에 쓰이지 않는다. 사진 입력은 공급자의 안전 검사 대상이며, 금지 콘텐츠 의심 시 별도 검토를 위해 보관될 수 있다.

이전 익명 선생 경로의 외부 처리

이전 익명 선생 경로의 인터넷 권한은 별도 동의한 이기자 선생의 Supabase 익명 인증과 HTTPS 채팅·기억·답변 신고 요청, 별도로 켠 대화형 리캡의 휘발 질문·분류 요청에 사용한다. 앱은 공개용 Supabase project key만 가지며 OpenAI API key와 Supabase 관리자 key는 APK에 넣지 않는다. 위 로컬 위기 분기에 해당하지 않는 채팅과 리캡 요청은 대한민국 리전의 개발자 Supabase 프로젝트를 거쳐 OpenAI API로 전달된다. OpenAI 요청은 store=false로 보내고 privacy-preserving safety identifier를 사용한다. store=false는 Responses 응답을 애플리케이션 상태로 저장하지 않게 하지만, 별도 Zero Data Retention 승인을 받지 않은 기본 API 정책에서는 악용 방지 로그에 입력·응답이 포함돼 최대 30일 보관될 수 있고 법적 의무나 중대한 위해 방지 필요가 있으면 더 길어질 수 있다. 지원 모델의 prompt caching에는 암호화된 key/value tensor가 GPU 로컬 애플리케이션 상태로 최대 24시간 남을 수 있다. 이 데이터는 사용자가 명시적으로 제공하지 않는 한 OpenAI 모델 학습에 사용되지 않는다. 개발자 중계는 사용자 원문을 DB 행이나 로그에 저장하지 않고 요청·문맥 digest와 유한 상태만 저장한다. 사용자가 답변을 직접 신고한 경우에만 예외적으로 해당 AI 답변과 닫힌 사유를 별도 신고 기록에 복사하며 사용자 원문은 복사하지 않는다. 일반 선생 응답 유실 재생을 위한 구조화 결과와 대화형 리캡의 원문 없는 operation terminal은 24시간 뒤 만료되고 다음 실제 retention sweep에서 물리 삭제될 때까지 남을 수 있다. 사용자별·프로젝트별 일반 호출량 행은 최대 35일 보관될 수 있다. 앱 삭제로 token이 사라진 익명 계정이 무기한 고아로 남지 않도록 선생 전용 계정 표식과 마지막 성공한 인증 활동 시각 한 건을 저장한다. 이 정보는 광고업체에 보내거나 판매하지 않는다. 선생과 리캡을 사용하지 않으면 감시·차단·과업·장부는 이 서버 호출 없이 기기에서 계속 작동한다.

4. Android 백업과 기기 이전

Android 백업 또는 기기 이전이 켜져 있으면 운영체제가 계약, 장부, 설정과 분리 전 버전의 사진 일부를 사용자의 Google 계정 백업 영역이나 새 기기로 옮길 수 있다. 이는 이기자 개발자 서버로 보내는 전송이 아니다.

새 실행의 행동 문장·선택 제목·시작 사진·증언 표지와 사용자가 직접 저장한 자주 쓰는 과업은 클라우드 백업과 기기 이전에서 제외한다. 삭제 상태를 구분하기 위해 불변 장부에도 존재하는 taskRunId와 DELETION_PENDING 또는 DELETED 상태만 담은 표식은 백업되거나 새 기기로 이전될 수 있다. 이 표식에는 제목·행동 문장·사진 경로·증언 값이 없다. 복원된 기기에 장부만 있고 실행 자료와 삭제 표식이 모두 없으면 삭제됐다고 추정하지 않고 '이 기기에 자료 없음'으로 표시한다.

다른 기기에서 감시가 저절로 켜지지 않도록 감시 ON 복구 의도는 백업과 기기 이전에서 제외한다. 민감정보 공개문과 웹주소 접근성 별도 고지의 확인 기록도 제외하므로 복원된 기기에서는 두 고지를 다시 확인하고 감시와 접근성 서비스를 직접 켜야 한다.

공통 계정 기능의 기기 백업

계정 로그인 정보와 기능 세대·미완 요청·삭제 확인용 표지는 기기의 백업 제외 저장소에 둔다. 계정 대화의 화면 메모리와 확인 전 후보는 Android 백업으로 복원하지 않는다. 저장된 기억은 서버 자료이며 복호화 키를 Android 백업에 넣지 않는다. 사용자가 확인한 로컬 리캡은 기존 Room 장부와 함께 백업·기기 이전에 포함될 수 있다. 새 기기 로그인·기기 연결·기능 복구는 기존 서버 동의와 현재 기기 상태를 확인하며, 백업 복원만으로 새 전송이나 공유를 시작하지 않는다.

이전 익명 선생의 백업 제외 범위

이기자 선생의 별도 AI 전송 동의, 별도 대화형 리캡 동의, 암호화된 익명 인증 token, 암호화된 보류 요청 한 건, 암호화된 최근 대화와 선생 서버 삭제 단계 표식도 Android 백업과 기기 이전에서 제외한다. 새 기기에서는 다시 동의하고 새 익명 계정을 만든다. 사용자가 확인해 Room에 저장한 대화형 리캡은 장부와 함께 Android 백업이나 기기 이전에 포함될 수 있지만 자동 백업·복원을 보장하지 않는다.

선제적 차단 위임·살아 있는 lease와 암호화된 구조화 심문 기록도 Android 백업과 기기 이전에서 제외한다. 새 기기에서는 선제적 차단과 구조화 기록 사용을 다시 직접 켜야 한다.

살아 있는 Strict 계약·회차·출소·완충 상태도 Android 백업과 기기 이전에서 제외한다. 새 기기에서 과거 Strict가 자동 집행되거나 완화되지 않으며, 사용자가 새 계약을 다시 명시 확인해야 한다. 규칙 잠금·전체 잠금의 임의 식별자 원본과 전체 잠금 상태도 제외하지만, 규칙에 붙은 개별 잠금의 해제 시각과 식별자 사본은 규칙과 함께 백업되거나 새 기기로 이전될 수 있다. 새 기기에는 식별자 원본이 없으므로 그 잠금은 이 설치의 잠금으로 인정하지 않고 규칙은 일반 규칙으로 되돌아간다.

등록한 차단 도메인은 다른 로컬 설정처럼 Android 백업이나 기기 이전에 포함될 수 있다. 접근성 권한과 감시 ON 의도는 이기자가 새 기기에 자동으로 켜지 않으므로, 사용자가 새 기기에서 공개문을 확인하고 두 기능을 직접 켜기 전에는 웹주소를 읽거나 차단하지 않는다.

독립 앱 정책과 공유 일일 시간 제한의 규칙·ON/OFF·선택한 앱·도메인·요일별 시간창·quota·사용량과 아직 Room에 쓰지 못한 설정 변경 기록은 Android 백업이나 기기 이전에 포함될 수 있다. 복원된 기기에서는 공개문과 감시를 다시 직접 확인하기 전까지 앱·웹 차단을 집행하지 않는다.

5. 보관과 삭제

완료된 새 과업 실행 자료와 장부에는 별도 자동 삭제 기한을 두지 않는다. 사용자는 한 실행의 자료 또는 모든 실행 자료를 앱 안에서 삭제할 수 있다. 이 삭제는 행동 문장·선택 제목·시작 사진·증언 표지를 지우지만 수행 시간·지급·포기·세션 유실 같은 불변 장부 사건은 지우거나 다시 쓰지 않는다. 진행 중 실행의 자료를 지워도 타이머는 계속되며, 집행을 멈추려면 별도 포기를 선택해야 한다. 삭제가 끝났다는 표시를 위해 taskRunId와 삭제 상태만 담은 표식은 앱 데이터 삭제 또는 앱 삭제 때까지 남을 수 있다.

사용자가 직접 저장한 자주 쓰는 과업은 관리 화면에서 따로 수정·삭제한다. '모든 과업 자료 삭제'는 실행별 자료만 지우며 자주 쓰는 과업을 함께 지우지 않는다. 그룹이나 자주 쓰는 과업을 삭제해도 이미 기록된 장부는 함께 삭제되지 않는다.

분리 전 버전의 Room 장부 사건에는 과업 이름과 사진 경로가 이미 들어 있을 수 있다. 업데이트 전에 시작된 과업의 구버전 세션 표식이 남아 있고 계약이 아직 유효하면, 앱이 세션 유실을 마감하는 과정에서 그 과업 이름이 분리 전 형식의 장부에 기록될 수 있다. 정상 마감 뒤 구버전 표식의 이름과 사진 경로는 지운다. 분리 전 장부의 과업 이름과 사진 경로, 이전 버전 사진은 현재 실행 자료 삭제 기능으로 개별 삭제하지 못하며, Android 설정의 앱 데이터 삭제 또는 앱 삭제 때 함께 지워진다.

독립 앱 정책 규칙을 OFF하면 규칙 정의는 남고 집행만 즉시 멈춘다. 규칙을 삭제하면 대상·제한 원문을 포함한 현재 규칙 정의가 즉시 사라진다. 두 동작은 Room 기록 장애로 미루지 않고 로컬 설정에 먼저 반영하며, 실패한 장부 기록만 다시 시도한다. 이미 Room에 기록된 scope=app_policy 사건은 규칙 OFF·삭제와 함께 지워지지 않는다.

Strict 고정기간에는 계약 화면에서 확인한 만기·회차당 한 번의 출소심사·자동연장·완충 약관을 적용하며 앱 안 중도 파기·완화·OFF·삭제를 제공하지 않는다. 완충이 끝나면 같은 표적·허용량의 일반 일일 시간 제한 규칙을 남긴다. Strict 현재 상태는 앱 데이터 삭제나 앱 삭제 때 지워지고, scope=strict_v1 장부 사건은 Strict 완료와 함께 자동 삭제되지 않는다. Android 권한 해제·강제 종료·앱 삭제 같은 운영체제 통제를 방해하지 않는다.

별도 차단 도메인은 웹사이트 차단 카드에서 하나씩 즉시 삭제할 수 있다. 담보 도메인은 담보 그룹 편집에서 빼거나 그룹 계약을 즉시 파기할 수 있다. 당일 담보 계보와 이미 집계된 그룹 사용시간·장부 전이는 오전 6시 마감과 판정 정합을 위해 현재 계약 정의 삭제와 함께 지워지지 않는다. 이기자는 방문한 전체 URL을 장부나 별도 방문 기록으로 보관하지 않는다.

구조화 심문 기록은 최대 35일·최대 64건 중 먼저 닿는 상한까지만 기기에 암호화해 보관한다. 선제적 차단 설정의 `심문 기록 지우기`, 구조화 기록 opt-in 해제, 선제적 차단 전체 권한 끄기는 이 기록을 즉시 지운다. AI 연결 해제는 로컬 연결 마무리 과정에서 이 기록을 지운다. 이전 익명 선생 서버 계정 삭제는 서버 삭제가 확인됐거나, 사용자가 서버 삭제 미확인 상태에서 이 기기 연결만 마무리하기로 확인한 뒤 로컬 마무리 과정에서 이 기록을 지운다. Room의 적용·취소·재잠금·만료 영수증은 집행 장부이므로 이 삭제와 섞지 않는다.

사용자가 확인한 대화형 리캡은 자동 만료시키지 않는다. 기록 관리 화면에서 한 건 또는 확인 기록 전체를 삭제할 수 있으며, 삭제한 요약·날짜·출처는 숨겨 보관하지 않는다. 삭제가 중단되면 내용 없는 복구 표식만 남겨 다음 실행에서 같은 삭제를 마무리한다. 대화형 리캡 동의를 끄거나 이전 익명 선생 서버 계정을 삭제해도 이미 확인한 로컬 리캡은 자동 삭제하지 않는다.

공통 계정 기능의 철회와 삭제

이 기기에서 로그아웃하면 로컬 로그인 정보를 지우고 기존 기기 세대의 모듈 자격을 종료하도록 요청한다. 서버 종료 확인이 실패하면 미확인 상태를 알리며, 로그아웃을 계정 삭제로 표시하지 않는다. 기능별 동의 철회는 새 사용을 막는 절차이고 본인 자료 정리를 위한 권리는 별도로 남는다. 앱 삭제·기기 데이터 삭제만으로 서버 자료까지 즉시 삭제되지는 않는다. 사진 비교 자료 정리와 기기 사진 삭제도 별개이며, 앱은 서버 완료를 확인하지 못했으면 완료로 표시하지 않는다.

기억 삭제 요청에서는 해당 기억의 서비스 사용을 막고 암호문 행 삭제, 독립 키 저장소의 해당 키 제거, 복원 방지 기록 추가를 각각 확인한다. 정리 실패나 응답 유실이 있으면 미확인 자료와 처리 표지를 보존하고 완전히 삭제됐다고 표시하지 않는다. 서버가 이 처리의 성공을 확인한 뒤에만 자료 정리 완료로 안내한다. 이는 공급자 백업까지 물리적으로 소거됐다는 확인은 아니다. 내용 없는 삭제·복원 방지 기록은 백업에서 삭제 자료가 되살아나는 것을 막기 위해 남길 수 있다. 동의 철회나 계정 삭제가 기기의 차단·경제 장부·확인한 리캡을 임의로 지우지는 않는다. 모듈별 자료 정리는 각 화면에서 별도로 진행한다. 공통 계정·동의 자료와 활성 기억 전체에 일률적인 24시간 자동 삭제를 적용하지 않는다. 선생·리캡의 서버 자료 삭제 후에도 당일 사용량 보존을 위한 내용 없는 작업 행이 남을 수 있다.

공통 계정 전체 삭제 요청

앱의 가입·로그인 화면에서 ‘계정 삭제 범위 확인…’을 누르거나, https://kwonjungjin.github.io/igija-privacy/account-delete/ 에서 사용하던 카카오 계정으로 본인확인한 뒤 삭제 범위를 읽고 명시적으로 요청할 수 있다. 웹 본인확인 과정에서 Supabase Auth의 인증 계정·로그인 기록이 생성될 수 있으나 이기자 계정을 새로 등록하거나 모듈 사용에 동의하지는 않는다. 삭제 요청이 시작되면 새 기능 사용을 막고 연결된 사진 비교·계정 선생·기억·리캡·스쿼드의 서버 자료 정리와 기억 키 폐기·복원 방지 처리를 확인한 뒤 로그인용 인증 계정을 마지막에 삭제한다. 카카오 계정 자체는 삭제하지 않는다. 기기에만 남은 차단 규칙·과업·경제 장부·확인한 리캡·내보낸 파일과 이전 익명 선생 자료는 이 요청의 삭제 대상이 아니다. 신고·처리 이력의 잔여 보존 기간, 백업·공급자 로그와 복원 방지 장부의 보존 한계도 그대로 적용한다.

요청을 보낸 것과 삭제 완료를 구분한다. 로그인 실패나 자료가 보이지 않는다는 이유만으로 성공으로 안내하지 않으며, 서버에 보존된 정리·인증 계정 삭제의 성공 확인을 조회했을 때만 완료로 표시한다. 응답 유실이나 실패로 완료가 불명확하면 새 삭제를 자동 반복하지 않고 미확인 상태로 남긴다. 이미 보낸 요청은 앱이나 웹에서 취소할 수 없다.

인증 계정 삭제 후에도 같은 요청의 결과를 확인하도록 요청 식별자와 독립적인 결과 조회용 비밀값을 생성한다. 앱은 이를 Android Keystore로 암호화해 백업 제외 영역에 두고, 웹은 현재 탭의 세션 저장소에 보관한다. 서버에는 조회용 값의 해시를 저장하며 원문 값은 저장하지 않는다. 이 값은 해당 요청의 결과 조회에만 쓰이고 새 삭제나 다른 자료 조회 권한을 주지 않는다. 결과 조회는 요청 뒤 최대 30일 동안 유효하며, 만료된 서버 조회 표지는 제한된 정리 작업이 성공할 때 회수한다. 앱 데이터 삭제·기기 변경·브라우저 탭 종료나 저장소 삭제로 조회 정보가 사라지면 이 경로로 결과를 다시 확인하지 못할 수 있다. 웹의 로그인용 인증값은 메모리에만 두며 PKCE 본인확인용 임시 값은 탭의 세션 저장소에서 최대 10분 동안만 사용한다. 완료된 삭제 처리 기록은 기존 보존 규칙에 따라 회수하지만, 실패·미확인 요청과 중복 삭제 방지 표지는 해결 전까지 남을 수 있다. 이것을 모든 자료의 물리 삭제 완료로 안내하지 않는다.

독립 키 저장소의 삭제와 보존

기억 삭제로 해당 키 항목을 제거해도 공급자 내부 사본의 물리 소거를 즉시 확인할 수는 없다. Google Cloud의 처리 약정은 복구할 수 없는 삭제 지시를 합리적으로 가능한 빠른 시점에, 최대 180일 이내 이행하도록 정하되 법적 보관 의무를 예외로 둔다. 이 기간은 이기자의 삭제 버튼 응답 시간이나 기억을 서비스에서 다시 사용할 수 있는 기간을 뜻하지 않는다. 내용 없는 복원 방지 장부는 삭제된 기억의 키를 다시 등록하지 못하게 하는 데 사용한다. 현재 장부에 일률적인 자동 삭제 기한을 약속하지 않으며, 백업과 독립 키 저장소의 보존 조건을 확인하기 전에는 장부 전체를 자동 회수하지 않는다.

이전 익명 선생의 연결 종료·서버 삭제

'새 대화'는 대화 vault 삭제가 성공한 뒤 현재 USER·TEACHER 대화만 비우며 확인 기억·익명 계정·호출량·선제적 차단 상태는 유지한다. 전송·기억·신고·계정 삭제가 진행 중이거나 응답 확인 보류가 남아 있으면 새 대화를 시작하지 않는다. '서버 데이터는 남기고 이 기기 연결만 끄기'는 이 기기의 AI 전송 동의, 암호화된 인증 token, 암호화된 보류 요청과 최근 대화를 지운다. 확인 기억·사용자가 직접 신고한 AI 답변과 사유·익명 계정은 개별 철회나 선생 서버 계정 삭제 요청이 없으면 마지막 성공한 선생 인증 활동 뒤 90일 동안 활성 데이터베이스에 남을 수 있다. 90일이 지나면 운영 보존 정리 대상이 되지만 자동 scheduler의 정시 실행과 정확히 90일째의 물리 삭제는 보장하지 않는다. 실제 retention sweep이 실행될 때 계정과 연결 데이터가 삭제될 수 있다. Android에서 앱 데이터만 지우거나 앱을 바로 삭제하면 서버에 즉시 삭제 신호를 보낼 수 없으므로, 즉시 서버 삭제를 요청하려면 먼저 앱 안의 '선생 서버 계정 삭제'를 실행해야 한다. 이 버튼을 다시 확인하면 인증된 현재 익명 계정과 그 계정에 연결된 선생 턴·호출량·확인 기억·신고한 AI 답변과 사유를 개발자가 통제하는 활성 데이터베이스와 Auth에서 삭제하도록 요청한다. 앱은 서버의 exact 성공 응답을 받은 경우에만 삭제 완료로 표시한다. 서버가 명시적으로 실패를 응답했거나 같은 익명 계정을 인증하지 못해 삭제 요청 전 단계에서 멈춘 경우에는 실패로 표시한다. 보존된 인증 상태가 허용하면 같은 계정 재시도 경로를 열지만 재시도 성공을 보장하지 않는다. 네트워크 중단·응답 손상·프로세스 종료처럼 성공 여부를 구분할 수 없는 경우에는 삭제됐다고도 남아 있다고도 단정하지 않는다. 실패·미확인 상태와 서버 성공 뒤 기기 정리가 끝나지 않은 상태는 원문 없는 유한 표식으로 백업 제외 SharedPreferences에 남기고 새 AI 계정과 채팅을 열지 않는다. 실패·미확인 상태에서는 보존된 인증 상태가 허용하면 같은 익명 세션으로 다시 시도하거나, 서버 완료가 확인되지 않았음을 고지받고 이 기기의 선생 연결만 지울 수 있다. 후자를 선택하면 같은 세션 재시도 권한을 버리고 서버 삭제는 미확인으로 남는다. 90일 뒤 운영 정리 대상이 될 수 있지만 자동 삭제를 보장하지 않고, 익명 계정 ID와 token을 지운 뒤에는 문의로 그 계정을 식별해 개별 삭제할 수 있다고 보장하지 않는다. 문의는 일반적인 삭제 절차와 보존 한계 안내에만 사용할 수 있다. 이 버튼과 연결 마무리는 차단·장부·과업·사진·확인 리캡을 지우지 않는다. 삭제 전 데이터베이스 사본은 운영 백업에 남아 있을 수 있다. 현재 Supabase Pro 플랜은 최근 7일의 일일 백업을 복원할 수 있으며 별도 시점 복구(PITR)는 사용하지 않는다. 이 복원 가능 기간을 모든 물리 사본이 정확히 7일째 삭제된다는 보장으로 표시하지 않는다. 백업 사본은 일반 서비스 조회에 쓰지 않는다. 공급자의 모든 물리 사본이 제거되는 시점은 앱에서 확인할 수 없다. OpenAI의 이미 생성된 악용 방지 로그는 이기자 선생 계정 삭제로 즉시 지울 수 없으며, 이 버튼은 OpenAI에 별도 로그 삭제 요청을 보내지 않는다.

앱 안에는 모든 계약·장부·과업·사진·리캡을 한 번에 지우는 전체 초기화 버튼을 두지 않는다. 기기 안의 전체 앱 데이터를 지우려면 Android 설정의 이기자 앱 정보에서 저장공간의 앱 데이터 삭제를 실행하거나 앱을 삭제할 수 있다. 이 운영체제 동작은 선생 서버 계정 삭제 요청과 별개다. Android 백업 사본은 기기 또는 Google 계정의 백업 설정에서 별도로 관리해야 하며, 개발자는 기기나 Google 계정의 백업을 원격으로 열거나 삭제할 수 없다.

6. 권한과 사용자 선택

사용정보 접근을 끄면 앱 전환을 볼 수 없어 사용 시간 계산과 차단 판단을 수행하지 못한다. 다른 앱 위 표시를 끄면 앱 사용 계약의 차단 화면을 보여 줄 수 없다. 웹주소 차단 화면은 별도로 켠 접근성 서비스가 표시한다. 상시 알림을 표시할 수 없으면 감시를 시작하지 않거나 실행 중인 감시를 멈춘다.

사용정보 접근이나 다른 앱 위 표시가 없거나 앱 정책 설정이 손상된 때에는 독립 앱 정책과 공유 일일 시간 제한을 fail-open하고 남아 있는 앱 정책 차단 화면을 제거한다. 사용자가 일반 규칙을 OFF하거나 삭제하면 장부 기록보다 먼저 집행을 멈춘다. Strict 계약 자체가 손상되면 해당 Strict를 fail-open하지만, 유효한 계약에서 시간 경과만 불명확하면 현재 차단·완충 사용량은 유지하고 만기·출소·일일 초기화 같은 완화 전이만 멈춘다.

앱을 열거나 공개문을 확인했다는 이유만으로 카메라 권한을 요청하지 않는다. 사용자가 과업 선언 화면에서 '시작 사진 찍기'를 누른 때만 Android에 CAMERA 권한을 요청한다. 권한을 거부하면 사진이나 세션을 만들지 않고 과업 선언 화면에 남는다.

웹주소 접근성 서비스를 끄면 주소 표시줄을 검사하지 않고 웹사이트 차단이나 담보 웹사이트 사용시간 계산을 수행하지 않는다. Android 12 이하에서는 cache와 하위 항목 선반입을 끄는 현재 최소수집 조건을 충족하지 못해 주소 표시줄도 검사하지 않고 차단·차감하지 않는다. Android 13 이상에서 이 서비스는 위에서 밝힌 조건에 따라 검사 대상 브라우저의 미리 식별한 주소창 항목을 기기 안에서 비교하고, 선택 도메인일 때만 같은 그룹 사용시간을 계산하며, 잔액이 없거나 굿나잇 시간인 경우 차단 오버레이를 표시한다. 주소를 확실히 읽지 못하면 차단·차감하지 않는다. 오버레이는 key focus를 받지 않고 fresh 차단 판정이 없으면 유한 시간 안에 제거되는 후보 구조다. 화면의 버튼을 대신 누르거나 설정을 바꾸지 않는다. 차단 화면의 '이전 페이지로 돌아가기'를 누르면 Android Back을 한 번 요청하되, 요청 성공만으로 허용 주소라고 단정하지 않는다. fresh 주소가 계속 차단이거나 일시 확인 불가이면 화면을 유지하고, 허용 주소·다른 앱·서로 모순되는 주소 후보·권한 조건 해제이면 오차단을 피하려 화면을 걷는다. Back 요청 실패 자체로 화면을 걷거나 Back을 자동 반복하지 않는다. '구글로 이동'을 누르면 같은 브라우저에 구글의 고정 주소를 새 탭으로 열도록 요청한다. 현재 방문 주소나 검색어는 이 요청에 포함하지 않고, 기존 탭의 이력을 지우거나 대체하지 않는다. 구글 열기를 자동으로 실행하거나 반복하지 않으며, 시스템 Back 키를 홈 동작으로 바꾸지 않는다. 접근성 권한은 Android 설정에서 언제든 끌 수 있다.

감시를 명시적으로 끄면 정상 재부팅 뒤에도 꺼진 상태로 둔다. 정상 재부팅 뒤 자동 복구는 완료된 계약, 확인한 민감정보 공개문, 명시적으로 켠 감시, 표시 가능한 상시 알림이 모두 있을 때만 시도한다. Android 설정의 강제 종료는 우회하지 않는다.

화면이 꺼진 뒤에도 감시를 계속하려면 앱 정보의 배터리 설정에서 '제한 없음'을 선택해야 한다. 권한을 허용하지 않거나 감시를 끄더라도 계약 편집과 앱 삭제를 방해하지 않는다.

7. 보호 조치와 한계

사용자가 직접 내보낸 파일을 제외한 앱 내부 로컬 데이터는 Android 앱 전용 내부 저장 영역과 앱 샌드박스 안에 둔다. 새 과업 실행 자료는 no-backup 저장소에 두고 CameraX 촬영본은 방향을 화소에 반영한 새 JPEG로 다시 쓰므로 원본의 EXIF·GPS·내장 썸네일을 보존하지 않는다. 사진·장부에는 별도의 앱 자체 파일 암호화를 추가하지 않는다. 이전 익명 선생의 access·refresh token, 모호한 원격 실패의 보류 요청 한 건, 최근 대화는 서로 다른 Android Keystore의 non-exportable AES-GCM key로 암호화한다. 최근 대화 암호문은 JSON 평문 기준 96KiB를 넘기지 않는다. 앱은 cleartext 네트워크를 금지하고 hosted Supabase HTTPS origin만 선생 endpoint로 인정한다.

이전 버전의 외부 앱 전용 사진 폴더는 Android 9 이하에서 저장소 권한을 가진 다른 앱이 접근할 가능성이 있다. 새 사진은 내부 앱 전용 저장소를 사용한다.

Google Play로 설치한 경우 Google은 자체 정책에 따라 충돌·ANR 같은 진단 정보를 처리하고 Play Console에 제공할 수 있다. 이기자에는 별도 Crashlytics·Sentry 등의 수집 SDK가 없다.

S24 SM-S921N·Android 16(API 36)의 삼성 인터넷 30.0.0.67은 현재 지원 검수 대상이다. versionCode 10 실기기 검사에서 주소 판정과 차단 화면 부착은 확인했지만, 기존 active-root 재검사가 차단 화면 자체를 읽어 650ms 뒤 제거되는 회귀를 발견했다. 입력 포커스를 가진 브라우저 창만 다시 읽는 수리와 상태바 갱신 이벤트를 이탈로 오판하지 않는 수리를 versionCode 14 후보에 넣었다. 이 후보의 실기기 시험은 같은 S24의 Brave 정식판 152.1.94.119에서만 했다. 거기서는 등록 도메인의 실제 주소 노출·주소 판정·차단 화면 부착과, 차단 화면이 정각 상태바 갱신을 다섯 번 넘겨 5분 이상 유지되는 것을 확인했다. Brave의 허용 전환 제거·탭 전환·redirect·Back·HOME 이탈과 삼성 인터넷 30.0.0.67·Chrome·Opera의 모든 항목은 이 후보에서 아직 시험하지 않았으므로 통과로 세지 않는다. Chrome 150은 이 S24에서 사용 중지 상태라 확인하지 않았다. Opera 정식판은 exact 주소창 ID만 코드에 고정한 DEVICE_UNVERIFIED 로컬 지원 대상이며, Opera 100에서는 주소창 resource 후보만 확인했다. Opera는 S24에서 실제 주소 노출·차단·탭 전환·redirect·Back·HOME·overlay lease를 검수하기 전에는 통과로 세지 않는다. Adblock Browser 3.12.1과 FREE ADBLOCKER BROWSER 139는 접근성 검사 대상에 넣지 않는다.

S21 exact 구성인 SM-G991N·Android 15(API 35)의 일반 탭 UI에서, Chrome 150.0.7871.186은 브라우저를 미리 연(warm) 상태의 허용 주소→차단 주소→HOME 이동 검사를 3/3 통과했다. 같은 S21 구성의 이전 Chrome 131.0.6778.260과 삼성 인터넷 30.0.0.67은 이전 실행 계보의 더 넓은 핵심 차단·내비게이션 검수를 통과했다. 이 S21 결과는 S24의 다른 브라우저 검수 결과로 합치지 않는다. 다른 기기·Android 버전·브라우저 버전의 일반 지원은 아직 확정하지 않았다. 웹사이트 차단은 Android 13 이상에서 현재 주소를 주소 표시줄 접근성 노드로 내놓고 이기자가 그 구조를 인식할 수 있는 화면에서만 작동한다. 브라우저 업데이트로 주소 표시줄 구조가 바뀌거나 비포커스 접근성 오버레이 아래에서 fresh 주소창 재검사가 성립하지 않으면 차단을 놓칠 수 있다. 현재 URL을 접근성 트리에 내놓지 않는 내부 브라우저 화면은 이 방식으로 차단할 수 없다. Beta·Dev·Canary·Nightly·Opera Mini, Firefox와 그 밖의 파생 브라우저, 네이버·카카오 내부 브라우저 지원을 보장하지 않는다.

8. 방침 변경과 문의
