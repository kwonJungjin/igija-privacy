이기자 개인정보처리방침

시행일: 2026년 8월 15일 · 앱: 이기자 · 운영 주체: 이기자 · 문의: weneedsomeigija@outlook.com

이기자는 사용자가 정한 앱 사용 계약과 독립 앱 정책을 기기에서 관찰·집행하고, 사용자가 고른 웹사이트 차단 설정을 적용하는 Android 앱이다. 선택 기능인 '이기자 선생'은 별도 AI 전송 동의 뒤 Supabase 익명 인증과 개발자 서버 중계를 사용한다. 광고·분석 SDK는 사용하지 않는다.

1. 처리하는 정보

앱 사용정보

사용정보 접근을 허용하면 이기자 감시 서비스가 시작된 뒤 첫 성공한 Android 사용정보(UsageStats) 조회에서 기기가 부팅된 뒤의 범위 중 최대 24시간에 해당하는 앱 전환 기록을 한 번 확인한다. 이 첫 조회는 직전 화면 앱을 놓치지 않고 감시의 최초 상태를 정하기 위한 초기 seed이며, 조회 결과 전체를 보존하지 않고 그 범위에서 가장 최근에 포그라운드로 전환한 1건만 서비스의 초기 목격으로 보존한다. 그 뒤 감시 서비스의 일반 조회와 대시보드 조회는 최근 10분의 앱 전환 기록을 확인한다. 두 조회 범위에는 계약 대상이 아닌 다른 앱의 패키지명과 전환 시각도 포함될 수 있다. 감시 중에는 조회한 원기록 전체가 아니라 앱 전환 또는 차단 상태가 바뀐 시점의 패키지명, 시각, 차단 상태만 기기 안의 장부에 저장한다.

설치 앱 정보

사용자가 '앱 목록 불러오기'를 누르면 런처에서 실행할 수 있는 설치 앱의 이름, 패키지명, 아이콘을 읽는다. 전체 목록과 아이콘은 선택 화면에만 사용하고 목록 자체를 저장하지 않는다. 사용자가 선택한 앱의 패키지명은 계약과 규칙 이력에 저장한다.

독립 앱 정책

독립 앱 정책은 Android 사용정보(UsageStats)에서 현재 화면 앱의 패키지명을 읽어 저장된 규칙과 비교한다. 사용자가 직접 만든 규칙의 ID·이름·저장 순서·ON/OFF, 선택한 앱 패키지명, 항상 차단 또는 요일·시작·종료 시간창은 앱 정책용 로컬 SharedPreferences에 저장한다. 설치 앱 전체 목록과 아이콘은 저장하지 않는다.

브라우저 웹주소

사용자가 등록한 도메인을 차단하기 위해 다음 정보를 처리한다. Android 13 이상에서 사용자가 별도 접근성 고지에 동의하고 Android 접근성 설정에서 '이기자 웹주소 차단'을 직접 켠 뒤, 사용정보 접근이 허용되고 이기자 감시가 실행 중이며 차단 목록이 있을 때만 접근성 서비스가 Chrome 정식판과 삼성 인터넷 정식판의 창 변경·창 내용 변경·입력 포커스 이벤트를 받도록 설정한다. Android가 전달하는 접근성 이벤트에는 화면 메타데이터가 포함될 수 있다. 이기자는 접근성 cache와 하위 항목 선반입을 끄고 현재 활성 창의 앱 식별자를 확인한 뒤, 같은 검사 대상 브라우저일 때만 미리 정한 주소창 항목을 찾는다. 주소 입력칸이 선택된 동안에는 반환 노드의 문자열을 차단 판단에 사용하지 않는다. 선택이 풀리면 주소창 항목의 화면 글자와 접근성 설명 중 웹주소로 해석되는 도메인을 등록한 목록과 기기 안에서 비교한다. 검색어처럼 웹주소로 해석되지 않는 문자열도 주소창 노드에 포함돼 전달될 수 있다. 차단 화면이 보이는 동안에는 현재 활성 창의 앱 식별자를 다시 확인하고 같은 브라우저일 때만 주소창 항목을 짧은 간격으로 재검사한다. 다른 앱이면 그 앱의 하위 항목을 찾지 않고 차단 화면을 제거한다. 페이지 본문이나 일반 입력칸을 따로 찾거나 그 문자열을 차단 판단에 사용하지 않지만, Android가 이벤트나 반환 노드에 포함해 전달한 메타데이터 자체의 수신까지 막는다고 약속할 수는 없다. 사용자가 등록한 정규화 도메인은 차단 목록에 저장한다. 검사한 주소창 문자열과 방문한 전체 URL은 저장하지 않고 개발자에게 전송하지 않는다.

계약과 사용 상태

담보 그룹의 이름과 내부 ID, 선택한 앱의 패키지명, 사용자가 등록한 차단 도메인, 하루 예산, 굿나잇 시간, 사용 시간, 과업으로 받은 시간, 멀티플 단계와 날짜 상태를 저장한다.

과업과 시작 사진

사용자가 입력한 과업 이름과 수행 시간, 시작 사진, 시작·완료·포기·세션 유실 시각, 지급 시간과 자주 쓰는 과업을 저장한다. 완료된 시작 사진은 오늘의 인증을 표시하는 데 사용한다. 카메라 취소·명시 포기·세션 생성 실패 때 새 내부 사진을 정리하지만, 촬영 성공 뒤 앱 프로세스가 예기치 않게 끝나면 미완료 사진이 앱 데이터에 남을 수 있다.

앱 운영 장부

감시 ON·OFF와 복구 결과, 사용정보 접근의 해제·복구, 차단 표시·해제 시각, 규칙 변경, 재부팅 횟수, 시계 변경 감지, 일별 판정과 스트릭을 저장한다. 독립 앱 정책의 규칙변경과 그 시점의 전체 규칙 사본, 앱 전환·차단 상태가 바뀐 시점의 패키지명·시각·규칙 ID·차단 사유는 같은 Room 데이터베이스에 scope=app_policy로 분리해 저장한다. 이 범위의 사건은 몸값 경제의 일별 판정·스트릭·계보·리캡 입력에서 제외한다. 이 정보는 계약과 앱 정책 집행, 상태 복원, 장부와 리캡 표시에 사용한다.

선제적 차단과 구조화 심문 기록

사용자가 선제적 차단 설정에서 별도로 `취소 뒤 구조화 심문 기록 사용`을 켠 경우에만, 선택한 앱·닫힌 발동 조건·발동 상한·cooldown·일회성 lease를 기기에 저장한다. 조치를 취소한 뒤에는 사용자 문장에 1~360 범위의 숫자+`분`이 정확히 하나 있을 때 그 첫 숫자 주장, 첫 취소·재잠금·최종 취소 시각, 재잠금까지 걸린 시간, 취소 뒤 선택 앱의 foreground 체류시간을 연속 단조시계 관측이 확실한 경우에만 구조화해 저장한다. 5초를 넘는 관측 공백, 재부팅, process death, 화면 OFF·잠금, 사용정보 접근 실패가 있으면 실제 체류시간은 추정하지 않고 unavailable로 둔다. 사용자가 채팅에 쓴 자유서술 이유, 세부 사용 timeline, 다른 앱 목록, 방문 URL은 이 구조화 기록에 복사하지 않는다. 별도 AI 전송 고지까지 동의한 사용자가 채팅을 보낼 때에는 선택 앱의 표시 이름, 현재 조치 상태·종류·닫힌 발동 조건·기준 횟수와 같은 활성 계약·같은 앱의 최근 완료 구조화 기록 최대 3건에서 첫 숫자 주장·확실히 관측한 실제 사용 분·취소 또는 재잠금 결과만 개발자 서버를 거쳐 OpenAI로 보낼 수 있다. 앱 package, 계약·사건 ID, 자유서술 이유, 세부 timeline, 정확한 취소 시각은 이 AI 문맥에 넣지 않는다.

온보딩 진행 상태

첫 계약을 마치기 전에는 현재 단계와 편집 중인 그룹 이름, 예산, 선택 앱을 저장해 앱을 다시 열었을 때 이어서 진행한다. 민감정보 공개문과 웹주소 접근성 별도 고지의 확인 버전도 기기에 저장한다.

이기자 선생 채팅과 익명 계정

사용자가 별도 AI 전송 고지에 동의하고 이기자 선생 화면에서 채팅을 보낸 때에만, 채팅 원문과 앱이 미리 정한 유한한 축약 사실, 사용자가 직접 확인한 기억 명제를 처리한다. 축약 사실에는 활성 과업의 시작 사진 존재 여부와 오늘 지급 기록 존재 여부가 포함될 수 있고, 위 구조화 심문 기록을 별도로 켠 경우에는 선제 조치의 유한한 사실이 포함될 수 있다. 사진·지급 사실은 존재 여부만 나타내며 사진 내용이나 지급량을 나타내지 않는다. 다만 앱의 닫힌 로컬 규칙이 명시적인 자해·죽음·극단 위험 문구로 분류한 채팅은 폰 안에서 고정 안전 응답으로 끝내고 그 원문과 앱 문맥을 개발자 서버나 OpenAI로 보내지 않는다. 방문 URL 원문, 사진 원본·내용·경로·해시·판정 결과, 지급량, 설치 앱 전체 목록, Room 장부 payload는 선생 문맥으로 보내지 않는다. Supabase Auth가 임의 사용자 ID와 access·refresh token을 발급하며, 앱은 token을 Android Keystore의 AES-GCM key로 암호화해 백업 제외 SharedPreferences에 저장한다. 일반 채팅은 화면을 닫으면 기기에 보관하지 않는다. 사용자가 아직 서버에 보존된 원격 AI 답변에서 '문제 있는 답변 신고'를 누르고 닫힌 사유 하나를 선택하면, 서버는 해당 익명 계정에 연결된 AI 답변 본문·응답 digest·선택한 사유·안전 모드·모델 및 prompt 버전·신고 시각을 검토용 신고 기록으로 보존한다. 사용자의 채팅 원문은 이 신고 기록에 복사하지 않으며 자유서술 신고문도 받지 않는다. 폰 안의 고정 위기 응답과 다른 사용자의 답변은 신고할 수 없다. 다만 응답 성립 여부를 확인하지 못한 요청 한 건은 중복 provider 비용을 막고 같은 ID·같은 익명 계정으로만 재확인하기 위해 client_turn_id, Supabase 익명 사용자 ID, 사용자 문장, 당시의 닫힌 축약 문맥, 생성 시각을 Android Keystore의 별도 AES-GCM key로 암호화해 기기에 보류한다. 재확인은 생성 뒤 최대 1시간만 허용한다. 성공하거나 사용자가 명시적으로 폐기·AI 연결 해제·계정 삭제·앱 데이터 삭제를 하면 지운다. 손상되거나 1시간이 지난 보류 요청은 다시 전송하지 않는다. 현재 익명 계정과 일치하지 않는 보류 요청도 다시 전송하지 않으며, 사용자가 폐기할 때까지 암호화 상태로 남아 새 평상 요청을 막는다. 선생이 만든 기억 후보와 행동 초안은 사용자 확인 전에는 앱 상태를 바꾸지 않는다.

2. 이용 목적

처리한 정보는 사용자가 정한 앱 사용 계약과 독립 앱 정책 집행, 대상 앱 사용 시간 계산, 앱·시간창 차단 화면 표시, 등록 도메인 비교와 웹주소 차단 화면 표시, 담보 앱 선택, 과업 수행과 시간 지급 기록, 장부·오늘의 인증·리캡·스트릭 표시, 명시적으로 켠 감시의 정상 재부팅 뒤 복구, 권한·알림·저장 실패 상태 고지에 사용한다. 사용자가 별도로 켠 선제적 차단의 구조화 기록은 취소·재잠금 결과를 복원하고, 별도 AI 동의 뒤 사용자가 채팅에서 이유를 말할 때 확인 가능한 유한 숫자 사실을 선생 답변에 반영하는 데에만 사용한다. 이기자 선생 정보는 사용자의 채팅에 답하고, 확인 전 기억·행동 초안을 제안하고, 요청 중복·비용 상한·안전 분기를 적용하는 데에 사용한다. 사용자가 직접 만든 문제 답변 신고는 해당 AI 답변을 확인하고 안전·품질 문제를 개선하는 데 사용한다.

3. 저장 위치와 외부 전송

계약·현재 상태·온보딩 상태와 등록한 차단 도메인은 Android SharedPreferences에 저장한다. 독립 앱 정책의 규칙·ON/OFF·선택한 앱·요일별 시간창은 igija_app_rules SharedPreferences에 저장한다. 선제적 차단 위임·lease는 backup 제외 SharedPreferences에, 구조화 심문 기록은 Android Keystore의 별도 non-exportable AES-GCM key로 암호화한 backup 제외 SharedPreferences에 저장한다. 역사 장부와 일별 판정, scope=app_policy 사건은 Room 데이터베이스에 저장한다. 새로 촬영한 과업 사진은 내부 앱 전용 저장소에 저장한다. 이전 버전에서 촬영한 사진은 기존 외부 앱 전용 폴더에 남아 있을 수 있다.

이기자 앱의 인터넷 권한은 별도 동의한 이기자 선생의 Supabase 익명 인증과 HTTPS 채팅·기억·답변 신고 요청에 사용한다. 앱은 공개용 Supabase project key만 가지며 OpenAI API key와 Supabase 관리자 key는 APK에 넣지 않는다. 위 로컬 위기 분기에 해당하지 않는 채팅 요청은 대한민국 리전의 개발자 Supabase 프로젝트를 거쳐 OpenAI API로 전달된다. OpenAI 요청은 store=false로 보내고 privacy-preserving safety identifier를 사용한다. store=false는 Responses 응답을 애플리케이션 상태로 저장하지 않게 하지만, 별도 Zero Data Retention 승인을 받지 않은 기본 API 정책에서는 악용 방지 로그에 입력·응답이 포함돼 최대 30일 보관될 수 있고 법적 의무나 중대한 위해 방지 필요가 있으면 더 길어질 수 있다. 지원 모델의 prompt caching에는 암호화된 key/value tensor가 GPU 로컬 애플리케이션 상태로 최대 24시간 남을 수 있다. 이 데이터는 사용자가 명시적으로 제공하지 않는 한 OpenAI 모델 학습에 사용되지 않는다. 개발자 중계는 사용자 원문을 DB 행이나 로그에 저장하지 않고 요청·문맥 digest와 유한 상태만 저장한다. 사용자가 답변을 직접 신고한 경우에만 예외적으로 해당 AI 답변과 닫힌 사유를 별도 신고 기록에 복사하며 사용자 원문은 복사하지 않는다. 응답 유실 재생을 위한 구조화 결과는 최대 24시간, 사용자별·프로젝트별 일일 호출량 행은 최대 35일 보관될 수 있다. 앱 삭제로 token이 사라진 익명 계정이 무기한 고아로 남지 않도록 선생 전용 계정 표식과 마지막 성공한 인증 활동 시각 한 건을 저장한다. 이 정보는 광고업체에 보내거나 판매하지 않는다. 선생을 사용하지 않으면 감시·차단·과업·장부는 이 서버 호출 없이 기기에서 계속 작동한다.

사진 촬영에는 사용자가 선택한 카메라 앱을 사용하며, 사진 촬영을 위해 한 장의 저장 위치를 카메라 앱에 전달한다. 카메라 앱 자체의 처리는 해당 앱의 정책을 따른다.

4. Android 백업과 기기 이전

Android 백업 또는 기기 이전이 켜져 있으면 운영체제가 계약, 장부, 설정과 사진 일부를 사용자의 Google 계정 백업 영역이나 새 기기로 옮길 수 있다. 이는 이기자 개발자 서버로 보내는 전송이 아니다.

다른 기기에서 감시가 저절로 켜지지 않도록 감시 ON 복구 의도는 백업과 기기 이전에서 제외한다. 민감정보 공개문과 웹주소 접근성 별도 고지의 확인 기록도 제외하므로 복원된 기기에서는 두 고지를 다시 확인하고 감시와 접근성 서비스를 직접 켜야 한다.

이기자 선생의 별도 AI 전송 동의, 암호화된 익명 인증 token, 암호화된 보류 요청 한 건도 Android 백업과 기기 이전에서 제외한다. 새 기기에서는 다시 동의하고 새 익명 계정을 만든다.

선제적 차단 위임·살아 있는 lease와 암호화된 구조화 심문 기록도 Android 백업과 기기 이전에서 제외한다. 새 기기에서는 선제적 차단과 구조화 기록 사용을 다시 직접 켜야 한다.

등록한 차단 도메인은 다른 로컬 설정처럼 Android 백업이나 기기 이전에 포함될 수 있다. 접근성 권한과 감시 ON 의도는 이기자가 새 기기에 자동으로 켜지 않으므로, 사용자가 새 기기에서 공개문을 확인하고 두 기능을 직접 켜기 전에는 웹주소를 읽거나 차단하지 않는다.

독립 앱 정책의 규칙·ON/OFF·선택한 앱·요일별 시간창과 아직 Room에 쓰지 못한 설정 변경 기록은 Android 백업이나 기기 이전에 포함될 수 있다. 복원된 기기에서는 공개문과 감시를 다시 직접 확인하기 전까지 앱·웹 차단을 집행하지 않는다.

5. 보관과 삭제

기기 안의 완료된 과업 사진과 장부에는 별도 자동 삭제 기한을 두지 않는다. 사용자가 Android 설정에서 이기자의 앱 데이터를 삭제하거나 앱을 삭제할 때까지 기기에 남는다.

그룹이나 과업 프리셋을 삭제해도 이미 기록된 장부와 완료된 인증 사진은 함께 삭제되지 않는다.

독립 앱 정책 규칙을 OFF하면 규칙 정의는 남고 집행만 즉시 멈춘다. 규칙을 삭제하면 대상·제한 원문을 포함한 현재 규칙 정의가 즉시 사라진다. 두 동작은 Room 기록 장애로 미루지 않고 로컬 설정에 먼저 반영하며, 실패한 장부 기록만 다시 시도한다. 이미 Room에 기록된 scope=app_policy 사건은 규칙 OFF·삭제와 함께 지워지지 않는다.

차단 도메인은 웹사이트 차단 카드에서 하나씩 즉시 삭제할 수 있다. 이기자는 방문한 전체 URL을 장부나 별도 방문 기록으로 보관하지 않는다.

구조화 심문 기록은 최대 35일·최대 64건 중 먼저 닿는 상한까지만 기기에 암호화해 보관한다. 선제적 차단 설정의 `심문 기록 지우기`, 구조화 기록 opt-in 해제, 선제적 차단 전체 권한 끄기, AI 연결 해제·계정 삭제는 이 기록을 즉시 지운다. Room의 적용·취소·재잠금·만료 영수증은 집행 장부이므로 이 삭제와 섞지 않는다.

'서버 데이터는 남기고 이 기기 연결만 끄기'는 이 기기의 AI 전송 동의, 암호화된 인증 token, 암호화된 보류 요청, 현재 화면의 채팅을 지운다. 확인 기억·사용자가 직접 신고한 AI 답변과 사유·익명 계정은 개별 철회·전체 삭제가 없으면 마지막 성공한 선생 인증 활동 뒤 90일 동안 활성 데이터베이스에 남을 수 있고, 90일이 지나면 다음 일일 보존 정리에서 익명 계정과 연결 데이터를 삭제한다. Android에서 앱 데이터만 지우거나 앱을 바로 삭제하면 서버에 즉시 삭제 신호를 보낼 수 없으므로, 즉시 서버 삭제를 원하면 먼저 앱 안의 '계정·서버 데이터 전부 삭제'를 실행해야 한다. 이 버튼을 다시 확인하면 인증된 현재 익명 계정과 그 계정에 연결된 선생 턴·호출량·확인 기억·신고한 AI 답변과 사유를 활성 데이터베이스의 서버 트랜잭션에서 삭제한 뒤 기기의 token·보류 요청·동의도 지운다. 연결 해제나 계정 삭제 도중 기기 저장이 중단되면 새 AI 계정과 채팅을 열지 않는 진행 표식을 남기고, 앱 안에서 로컬 연결 해제를 마무리할 수 있게 한다. 이 마무리는 서버 데이터의 즉시 삭제를 보장하지 않으며, 서버 삭제 완료를 확인하지 못한 데이터는 아래 90일 정리 또는 문의를 통해 삭제할 수 있다. 현재 Supabase Pro 프로젝트는 매일 자동 백업되며 최근 최대 7일의 백업에 삭제 전 사본이 남아 있을 수 있다. 이 백업 사본은 일반 서비스 조회에 쓰지 않고 보존 기간 만료에 따라 사라진다. OpenAI의 이미 생성된 악용 방지 로그는 이기자 계정 삭제로 즉시 지울 수 없다. 네트워크나 서버 장애로 삭제가 끝나지 않으면 기기 token을 유지해 사용자가 다시 시도할 수 있게 하며, 아래 문의 주소로도 삭제를 요청할 수 있다.

기기 안의 전체 데이터를 지우려면 Android 설정의 이기자 앱 정보에서 저장공간의 앱 데이터 삭제를 실행하거나 앱을 삭제할 수 있다. Android 백업 사본은 기기 또는 Google 계정의 백업 설정에서 별도로 관리해야 하며, 개발자는 기기나 Google 계정의 백업을 원격으로 열거나 삭제할 수 없다.

6. 권한과 사용자 선택

사용정보 접근을 끄면 앱 전환을 볼 수 없어 사용 시간 계산과 차단 판단을 수행하지 못한다. 다른 앱 위 표시를 끄면 앱 사용 계약의 차단 화면을 보여 줄 수 없다. 웹주소 차단 화면은 별도로 켠 접근성 서비스가 표시한다. 상시 알림을 표시할 수 없으면 감시를 시작하지 않거나 실행 중인 감시를 멈춘다.

사용정보 접근이나 다른 앱 위 표시가 없거나 앱 정책 설정이 손상된 때에는 독립 앱 정책을 fail-open하고 남아 있는 앱 정책 차단 화면을 제거한다. 사용자가 규칙을 OFF하거나 삭제하면 장부 기록보다 먼저 집행을 멈춘다.

웹주소 접근성 서비스를 끄면 주소 표시줄을 검사하지 않고 웹사이트 차단을 수행하지 않는다. Android 12 이하에서는 cache와 하위 항목 선반입을 끄는 현재 최소수집 조건을 충족하지 못해 주소 표시줄도 검사하지 않고 차단하지 않는다. Android 13 이상에서 이 서비스는 위에서 밝힌 조건에 따라 검사 대상 브라우저의 미리 식별한 주소창 항목을 기기 안에서 비교하고 차단 오버레이를 표시한다. 오버레이는 key focus를 받지 않고 fresh 차단 판정이 없으면 유한 시간 안에 제거되는 후보 구조다. 화면의 버튼을 대신 누르거나 설정을 바꾸지 않으며, 차단 화면의 홈 버튼을 누른 때만 Android 홈 동작을 요청한다. Back 키를 홈 동작으로 바꾸지 않는다. 접근성 권한은 Android 설정에서 언제든 끌 수 있다.

감시를 명시적으로 끄면 정상 재부팅 뒤에도 꺼진 상태로 둔다. 정상 재부팅 뒤 자동 복구는 완료된 계약, 확인한 민감정보 공개문, 명시적으로 켠 감시, 표시 가능한 상시 알림이 모두 있을 때만 시도한다. Android 설정의 강제 종료는 우회하지 않는다.

화면이 꺼진 뒤에도 감시를 계속하려면 앱 정보의 배터리 설정에서 '제한 없음'을 선택해야 한다. 권한을 허용하지 않거나 감시를 끄더라도 계약 편집과 앱 삭제를 방해하지 않는다.

7. 보호 조치와 한계

새로 만드는 데이터는 Android 앱 전용 내부 저장 영역과 앱 샌드박스 안에 둔다. 사진·장부에는 별도의 앱 자체 파일 암호화를 추가하지 않는다. 이기자 선생의 access·refresh token과 모호한 원격 실패의 보류 요청 한 건은 서로 다른 Android Keystore의 non-exportable AES-GCM key로 암호화한다. 앱은 cleartext 네트워크를 금지하고 hosted Supabase HTTPS origin만 선생 endpoint로 인정한다.

이전 버전의 외부 앱 전용 사진 폴더는 Android 9 이하에서 저장소 권한을 가진 다른 앱이 접근할 가능성이 있다. 새 사진은 내부 앱 전용 저장소를 사용한다.

Google Play로 설치한 경우 Google은 자체 정책에 따라 충돌·ANR 같은 진단 정보를 처리하고 Play Console에 제공할 수 있다. 이기자에는 별도 Crashlytics·Sentry 등의 수집 SDK가 없다.

S24 exact 구성인 SM-S921N·Android 16(API 36)의 삼성 인터넷 30.0.0.67에서는 허용 주소, exact·하위 도메인 차단, 유사 suffix·검색 query 허용, 허용 전환 뒤 차단 화면 제거와 차단 화면 HOME 이탈을 확인했다. Chrome 150은 이 S24에서 사용 중지 상태라 확인하지 않았다. Opera 100, Adblock Browser 3.12.1, FREE ADBLOCKER BROWSER 139는 주소창 resource 후보만 확인했으며 실제 차단·오차단·제거 검수를 마치기 전에는 접근성 검사 대상에 넣지 않는다.

S21 exact 구성인 SM-G991N·Android 15(API 35)의 일반 탭 UI에서, Chrome 150.0.7871.186은 브라우저를 미리 연(warm) 상태의 허용 주소→차단 주소→HOME 이동 검사를 3/3 통과했다. 같은 S21 구성의 이전 Chrome 131.0.6778.260과 삼성 인터넷 30.0.0.67은 이전 실행 계보의 더 넓은 핵심 차단·내비게이션 검수를 통과했다. 이 S21 결과는 S24의 다른 브라우저 검수 결과로 합치지 않는다. 다른 기기·Android 버전·브라우저 버전의 일반 지원은 아직 확정하지 않았다. 웹사이트 차단은 Android 13 이상에서 현재 주소를 주소 표시줄 접근성 노드로 내놓고 이기자가 그 구조를 인식할 수 있는 화면에서만 작동한다. 브라우저 업데이트로 주소 표시줄 구조가 바뀌거나 비포커스 접근성 오버레이 아래에서 fresh 주소창 재검사가 성립하지 않으면 차단을 놓칠 수 있다. 현재 URL을 접근성 트리에 내놓지 않는 내부 브라우저 화면은 이 방식으로 차단할 수 없다. Firefox, beta·dev·canary·파생 Chromium, 모든 브라우저와 인앱 브라우저 지원을 보장하지 않는다.

8. 방침 변경과 문의

처리 항목이나 기능이 바뀌면 이 방침과 앱 안의 공개문을 함께 갱신한다. 새 확인이 필요하면 공개문 버전을 올려 다시 확인을 받는다.
